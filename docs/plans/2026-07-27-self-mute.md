# Self-mute button (mic fab) + broadcast to other participants' avatars

## Context

Today the control bar's mic button (`room.html`) fully starts/stops the mic device and its mediasoup producer on every click — that's `MediaRoom.toggleMic()`, and `isMicMuted()` really means "no mic producer exists at all," not "muted while still on." The user wants a genuinely separate concept layered on top: a small self-mute toggle at the **top-left** of that same mic fab (mirroring the existing top-right device-picker arrow's exact visual treatment), which keeps the mic device/producer alive but silences the outgoing audio — implemented as `MediaStreamTrack.enabled = false`, the standard renegotiation-free WebRTC mute. Since the recording pipeline is just an RTP forward of whatever the producer sends, muting this way also means recordings naturally capture silence during the muted period — no backend recording changes needed at all.

This self-muted state must be visible to everyone else in the room: the muted user's avatar in the `participant-avatars` row (already built — `AvatarSpeakerBadge`/`ParticipantAvatar`) should go grayscale and show the same strikethrough speaker icon (`volume_off`) already used for the existing per-listener mute feature — reusing that exact visual treatment, not building a new one. Per your explicit requirement, a self-muted peer's avatar must also lose the hover/tap volume popover entirely (no point letting a listener "unmute" or adjust volume on a track that's silent because the speaker chose to mute) — while still showing the static muted glyph as an indicator.

Confirmed via research: this is new territory for the backend. Every existing room broadcast (`peer-joined`, `user-typing`, `active-speakers`, even `recording-state`) is fire-and-forget with no "catch up a late joiner on current state" mechanism. Self-mute needs real per-peer server-side state so someone who joins the room *after* another peer already self-muted still sees that correctly — the natural, minimal way to do this is add `micSelfMuted: boolean` right alongside `displayName`/`pictureUrl` on the server's per-peer state (`IPeerState`) and in the join-room ack's existing `peers: IPeerSummary[]` roster, exactly the same place those two fields already flow through.

## Backend (`spaces-nestjs-api-claude`)

- `src/room/interfaces/room.interfaces.ts`: add `micSelfMuted: boolean` to both `IPeerSummary` (~line 14) and `IPeerState` (~line 103).
- `src/room/room.service.ts`:
  - `joinRoom()` (~line 120): seed `micSelfMuted: false` in the `this.peers.set(...)` call (~line 147), and include `micSelfMuted: peer.micSelfMuted` in each pushed `IPeerSummary` (~line 135).
  - New method `setMicSelfMuted(peerId: string, muted: boolean): { roomName: string } | null` — looks up the peer, sets the flag, returns just enough for the gateway to broadcast (mirrors `closePeer()`'s return-shape style); `null` if the peer isn't found.
- `src/room/room.gateway.ts`:
  - `onJoinRoom`'s `peer-joined` broadcast (~line 200) gains `micSelfMuted: false` (a freshly-joined peer always starts unmuted).
  - New handler, right next to the chat-typing pair:
    ```ts
    @SubscribeMessage('mic-mute-changed')
    onMicMuteChanged(@ConnectedSocket() socket: Socket, @MessageBody() payload: { muted: boolean }) {
        const result = this.roomService.setMicSelfMuted(socket.id, payload.muted);
        if (!result) return;
        socket.to(result.roomName).emit('mic-mute-changed', { peerId: socket.id, muted: payload.muted });
    }
    ```
- Tests: extend `room.gateway.spec.ts` (`setMicSelfMuted: jest.fn()` added to the fake `roomService`) — broadcasts via `socket.to`, no-op when the service returns null. Add a focused case (new `room.service.spec.ts` if none exists, else extend it) for `setMicSelfMuted()`'s found/not-found behavior and confirm `joinRoom()`'s returned `peers` entries carry `micSelfMuted`.

## Frontend (`spaces-angular-claude`)

### `src/app/room/services/media-room.ts`
- `IJoinRoomAck.peers` (~line 45) and `joinRoom()`'s return type (~line 205) both gain `micSelfMuted: boolean` per entry — passed through unchanged at ~line 235.
- New signal: `isSelfMuted` (mirrors `isMicMuted`'s own signal/readonly pattern).
- New method:
  ```ts
  toggleSelfMute(): boolean {
      if (!this.localMicTrack) return this.isSelfMutedSignal(); // nothing to mute — mic isn't on
      const next = !this.isSelfMutedSignal();
      this.localMicTrack.enabled = !next;
      this.isSelfMutedSignal.set(next);
      return next;
  }
  ```
- `toggleMic()`'s existing "turning off" (~487-498) and "turning on" (~500-515) branches both add `this.isSelfMutedSignal.set(false)` — a full mic on/off cycle always starts fresh unmuted, right alongside where `localMicTrack`/`activeMicDeviceIdSignal` already get reset there.

### `src/app/room/models/chat-message.model.ts` + `src/app/room/services/chat.ts`
- `PeerSummary` gains `micSelfMuted: boolean`.
- `'peer-joined'` listener stores the new field from the event.
- New listener: `'mic-mute-changed'` → updates the matching presence entry's `micSelfMuted` by peerId (immutable map, same style as the existing presence updates).
- New outbound method `notifyMicMuteChanged(muted: boolean): void` — fire-and-forget `emitWithAck('mic-mute-changed', { muted })`, same `.catch(() => {})` pattern as `notifyTyping`/`notifyStoppedTyping`.

### `src/app/room/room.ts`
- `readonly isSelfMuted = this.mediaRoom.isSelfMuted;`
- New method:
  ```ts
  toggleMicMute(): void {
      const nowMuted = this.mediaRoom.toggleSelfMute();
      this.chat.notifyMicMuteChanged(nowMuted);
  }
  ```
- `toggleMic()` (the existing full on/off) extended so turning the mic back ON also resets the *broadcast* state (closes the edge case where a stale server-side `micSelfMuted: true` could leak to a late joiner after an off/on cycle):
  ```ts
  async toggleMic(): Promise<void> {
      await this.mediaRoom.toggleMic();
      if (!this.mediaRoom.isMicMuted()) {
          this.chat.notifyMicMuteChanged(false);
      }
  }
  ```
- `micFeeds()` computed (~line 103) gains a `selfMuted` lookup from presence, same Map pattern already used for `pictureUrl`.

### `src/app/room/room.html` + `room.scss`
- Mic fab's `.fab-with-device-menu` wrapper gains a new icon button, mirroring `.device-select-arrow`'s exact structure/positioning but at **top-left**, shown only while the mic is actually on (nothing to mute otherwise):
  ```html
  @if (!isMicMuted()) {
    <button mat-icon-button class="mic-self-mute-toggle" [matTooltip]="isSelfMuted() ? 'Unmute yourself' : 'Mute yourself'" (click)="toggleMicMute()">
      <mat-icon>{{ isSelfMuted() ? 'volume_off' : 'volume_up' }}</mat-icon>
    </button>
  }
  ```
  (`volume_up`/`volume_off` — the same speaker-icon family already used on the avatars, per your explicit ask for visual consistency, not a mic-themed icon.)
- Local avatar tile gains `[selfMuted]="isSelfMuted()"`; each `<app-participant-avatar>` in the `micFeeds()` loop gains `[selfMuted]="feed.selfMuted"`.
- `room.scss`: new `.mic-self-mute-toggle` rule — copies `.device-select-arrow`'s box/icon sizing verbatim, `top: -3px; left: -3px;` instead of `right`.

### `src/app/room/participant-avatar/participant-avatar.ts` + `.html`
- New input `selfMuted = input(false);`.
- `showControls` becomes `computed(() => !this.isLocal() && !this.selfMuted())` (replacing the inline `!isLocal()` in the template) — this is what removes the hover/tap volume popover for a self-muted peer, for both remote avatars and (now, since self-mute also applies to your own tile) the local one.
- Effective `muted` passed to the badge becomes `computed(() => this.mutedSignal() || this.selfMuted())` — ORs the listener's own local mute choice with the peer's broadcast self-mute state, so a self-muted peer's avatar always grays out/shows the muted glyph regardless of what any listener had chosen before.
- The `<audio>` volume/mute effect switches to this same effective-muted computed (defensive — the track is already silent at the source, but keeps the DOM element consistent).

### `src/app/shared/avatar-speaker-badge/` — static muted glyph when controls are hidden
Today the whole speaker-icon button (not just the popover) lives inside `@if (showControls())` — so simply forcing `showControls=false` would hide the muted indicator entirely, which is the opposite of what's needed. Restructure `avatar-speaker-badge.html`:
```html
@if (showControls()) {
  <button class="avatar-badge-speaker" ...>...</button>
  @if (popoverVisible()) { ... }
} @else if (muted()) {
  <div class="avatar-badge-speaker avatar-badge-speaker-static" aria-hidden="true">
    <mat-icon>volume_off</mat-icon>
  </div>
}
```
A plain non-interactive `<div>` (not `<button>`) reusing `.avatar-badge-speaker`'s exact positioning/sizing, plus a `.avatar-badge-speaker-static` modifier in `avatar-speaker-badge.scss` (`cursor: default; pointer-events: none;`) so there's no hover/focus affordance at all.
